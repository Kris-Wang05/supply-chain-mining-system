# Agent SOP

本文档把原始 SOP 转成 Codex 可执行的研究流程。目标不是给出买卖建议，而是生成可审计的候选表和证据链。

## 输入

输入可以是：

- 一条主线名称，例如 `AI先进封装`、`AI电力`、`立法造舰`。
- 一个锚点事实，例如某项法案拨款、链主产能承诺、已签合同或已确认产品路线图。

## 执行范围

Codex 默认只执行 Stage 0-5：

1. Stage 0：主线登记与周期定位。
2. Stage 1：锚点事实采集。
3. Stage 2：工序分解与必然接单推导。
4. Stage 3：标的映射与可交易性过滤。
5. Stage 4：覆盖空白与定价检验。
6. Stage 5：红旗筛查。

Stage 6-8 只输出待人工回答的问题，不替代人的判断。

## 来源规则

- 一级来源优先：政府文件、公司公告、财报电话会、10-K/10-Q、合同披露。
- 次级来源必须交叉验证。
- 每个数字必须带 `source_url`、日期和来源等级。
- 无法验证的数字必须标记 `[unverified]`，不得补写或推断成事实。

## 候选输出规则

每个候选必须包含：

- ticker 和交易所。
- 对应工序节点。
- 订单传导类型。
- 必然接单强度，1-5 分。
- 纯度比例或无法确认说明。
- 三项定价检验结果。
- 触发的 kill rules。
- 价格史备注。
- 综合评级：`A`、`B`、`C`、`坐标`、`出局`。

`A` 或 `B` 候选必须额外写一段 mispricing hypothesis：解释市场为什么还没定价它。

## 评级约束

- `A`：证据链完整、传导强、红旗少、定价检验全阴性或可解释。
- `B`：证据链较完整，但仍有覆盖、纯度、流动性或价格史瑕疵。
- `C`：可以跟踪，但暂不满足核心仓位或催化剂要求。
- `坐标`：不可交易或纯度过低，但可作为产业温度计。
- `出局`：触发 kill rule，或关键事实无法验证。
