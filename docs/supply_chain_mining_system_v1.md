# 产业链挖掘系统 v1.0 (Supply Chain Mining System)

> 用途:本文档同时是 (a) 交给 Codex 执行的 Agent 指令,(b) 人工分析的 SOP。
> 核心原则:**不对称只存在于"我的判断与市场定价的差"里。本系统的每一步都在回答:市场还没定价什么,以及为什么是我先知道。**
> 配套文件:catalyst_momentum_system_v2.md (入场与仓位执行层)

---

## 系统总览:八阶段流水线

```
Stage 0 主线登记 → Stage 1 锚点事实 → Stage 2 工序分解 → Stage 3 标的映射
→ Stage 4 定价检验 → Stage 5 红旗筛查 → Stage 6 催化剂建模 → Stage 7-8 执行与监控
```

分工:Stage 0-5 可由 Codex 自动化执行 (挖掘),Stage 6-8 由人工+AI 协作完成 (判断)。
每个 Stage 有明确的 kill criteria:候选标的在任一 Stage 被杀,立即出局,不进入下一 Stage。

---

## Stage 0:主线登记与周期定位 (Mainline Registry)

**目标**:维护一份"活跃主线"清单,并标注每条主线的生命周期位置。主线是不对称的变现通道:催化剂兑现时,接货的资金由主线叙事召唤。没有主线通道的催化剂 = 朝空旷山谷开枪。

**每条主线建一张卡片,字段**:
- `name`:主线名称 (如 AI先进封装 / AI电力 / 立法造舰 / 稀土脱钩)
- `anchor_facts`:支撑该主线的1-3个硬数字 (见 Stage 1)
- `lifecycle`:early / mid (甜区) / late
- `falsification_signals`:该主线的证伪信号清单 (如 hyperscaler 下调 capex 指引、设备交期正常化、二手 GPU 价格跳水)
- `junk_graft_density`:垃圾票嫁接密度 (近90天有多少老业务衰退的小票开始蹭该主线热词)。**这是周期定位的核心指标:嫁接密度高 = 晚期,收紧标准、降彩票仓**

**周期判定规则**:
- early:证据少、无人嫁接、主干票尚未重估 → 只配观察仓
- mid (甜区):主干已涨、qualification/首批订单落地、毛细血管未定价 → 主力猎场
- late:主干估值透支 + 嫁接密度高 → 只做主线上有真实盈利的票,或迁移到更早期主线

**Codex 执行**:每周扫描一次,更新嫁接密度 (搜索"[主线热词] + 小市值公司新闻稿",统计新增嫁接者数量),输出主线状态变更警报。

## Stage 1:锚点事实采集 (Anchor Facts)

**目标**:找到"写在公开文件里的硬数字"。锚点事实是整条推理链的地基,必须满足:有数字、有日期、有一手来源、已承诺/已立法/已签约 (不是预测)。

**合格锚点的类型与来源等级** (按可信度降序):
1. **立法/政府文件**:国会 CRS 报告、NDAA/拨款法案条文、预算文件 (congress.gov, comptroller.defense.gov)。例:FY2026 SCN 造舰账户$47.4B,其中$26.5B为强制性拨款;采购1艘LPD+1艘LHA+9艘LSM
2. **链主已公告的产能/capex 承诺**:财报电话会记录、官方新闻稿。例:CoWoS 月产能 2025底75k片 → 2026底120-130k片;hyperscaler 2026合计 capex ~$725B
3. **已签合同/backlog**:例:NVIDIA 锁定 CoWoS 年产能80-85万片;AWS backlog $364B
4. **已确认的产品路线图**:例:Rubin = 4倍 reticle + 12颗 HBM4;NVIDIA 下一代机架转800V直流
5. 行业研究机构数据 (TrendForce 等):次级来源,需两个独立来源交叉确认

**不合格的锚点**:管理层"目标"、分析师预测、pipeline (≠backlog)、MOU、LOI。

**输出 schema**:
```json
{"fact": "", "number": "", "date": "", "source_url": "", "source_tier": 1-5, "mainline": "", "confidence": "high/med/low"}
```

**Codex 执行**:对每条活跃主线,每月重跑一次锚点采集,标注新增/失效的锚点。所有数字必须带时间戳,无法确认时间的数字标记 unverified。

## Stage 2:工序分解与"必然接单"推导 (Process Decomposition)

**目标**:把锚点事实分解成工序/BOM,推导出哪些环节被机械性地强制接单。这是整个系统的智力核心。

**操作步骤**:
1. 把锚点对应的产品/项目拆成工序链 (如 CoWoS:TSV→interposer→RDL→键合→molding→减薄切割→测试) 或 BOM (如一艘LPD:消磁系统/动力/雷达/...)
2. 对每个环节回答:
   - **供给结构**:垄断 / 双寡头 / 分散?(垄断环节才有定价权和确定性)
   - **缩放函数**:锚点数字翻倍时,该环节需求是线性翻倍、超线性 (如多die封装的测试强度随die数超线性)、还是可选项?
   - **产能缺口**:现有产能能否承接?不能 → 必然有扩产订单
3. **"必然接单"判定**:锚点 → 该环节订单之间是否存在机械传导 (designed-in、sole-source、耗材按片计费、法定配套)?是 = 强候选;需要赢得竞标 = 弱候选

**推理深度规则**:一阶信息 (链主扩产) 市场定价最快,二阶 (谁必然接外溢) 慢,三阶 (接单者的设备/材料商) 最慢。**优先输出二阶和三阶节点**。

**经典传导模板** (可复用):
- 法案→舰体数→designed-in 独家分包商 (例:NDAA→LPD-33→AMSC 消磁系统)
- 链主产能→外包比例→OSAT (例:CoWoS→Amkor 18-19万片/年)
- 封装复杂度→检测/测试强度超线性 (例:多die→KGD探针卡/光学检测)
- 新架构→新材料 POR (例:玻璃基板→配套电镀/介电化学品)
- 新电压/新制冷标准→元件强制换代 (例:800VDC机架→GaN/SiC→外延设备)

**输出 schema**:
```json
{"anchor_fact_id": "", "node": "", "transmission": "designed-in/sole-source/per-unit-consumable/capacity-gap/competitive-bid", "scaling": "linear/superlinear/optional", "order_inevitability": 1-5}
```

## Stage 3:标的映射与可交易性过滤 (Ticker Mapping)

**目标**:把工序节点映射到上市公司,并过滤掉交易不到或纯度不足的。

**过滤规则**:
1. **市场可达性**:US / EU (含 Xetra、米兰、阿姆斯特丹) = 可交易;JP / TW / KR / HK = 标记为"认知坐标" (用其财报当温度计,不建仓)
2. **纯度测试**:该节点收入占公司总收入比例。>30% = 交易候选;10-30% = 需折价处理;<10% = 故事被稀释,降级为认知坐标 (例外:若该节点是公司的边际增量引擎且市场未定价,可保留,如 Q 的玻璃基板材料线)
3. **流动性底线**:日均成交额能容纳3个 tranche 进出且滑点<2%
4. **市值偏好**:<$3B 优先 (机构覆盖薄弱区),$3-10B 次之,>$10B 仅作底仓候选

**输出 schema**:
```json
{"ticker": "", "exchange": "", "node": "", "purity_pct": "", "market_cap": "", "tradable": true/false, "role_hint": "lottery/core/coordinate"}
```

## Stage 4:覆盖空白与定价检验 (Pricing Tests)

**目标**:验证"市场还没定价"是真的。三项测试,**三项全阴性才是真末端**:

1. **覆盖密度**:卖方分析师数量与构成。只有本土小行/paid research = 阴性;美资大行已覆盖 = 阳性 (末端身份终结)
2. **重估检查**:过去6个月该股相对其板块指数的超额涨幅。已独立重估 >50% = 阳性 → 必须回答"我的增量判断是什么",答不出则出局
3. **热词浓度**:管理层最近两次财报电话会/新闻稿中主线热词的使用频率变化。突然开始大量使用 = 接近被发现 (阳性偏中性);从不提及但业务实质相关 = 最佳 (信息差最大)

**附加检查:价格史考古**。对照锚点事实的公布日期与股价走势:锚点公布后股价未动 = 市场没读懂 (机会);锚点公布前股价已动 = 有人先知道 (跟随);锚点公布后已暴涨 = 迟到 (等回撤或放弃)。**不知道上一波为什么涨的标的,禁止入场。**

## Stage 5:红旗筛查 (Kill Rules)

以下规则按顺序执行,**任一触发即出局或降级**。这些规则每一条都对应一个真实的亏钱模式:

1. **叙事/合同背离杀**:pipeline、proposal、MOU 等叙事指标暴增,而 backlog (签约存量) 同比下降 → 直接出局。(模式:FCEL,pipeline +267% 但 backlog -9.9%)
2. **稀释成瘾杀**:历史上有 reverse split、ATM 协议在档、或12个月内2次以上增发 → 出局或仅限半注彩票,且"任何新增发公告 = 无条件离场"。(模式:AMPG/FCEL。原理:名义赔率1:5,稀释后实际1:1)
3. **关联方订单杀**:核心叙事的首笔收入来自持股关联方、子公司互售、或政府补贴 → 冻结,直到出现首笔非关联方、非补贴的商业订单。(模式:KOPN 与持股19.9%的 Fabric.AI)
4. **未读合同杀**:估值支柱是某大额合同,但 counterparty 身份/信用不明 → 读到合同原文前禁止入场。(模式:DGXX 的$1.1B匿名租户)
5. **嫁接模式杀**:老业务衰退 + 新叙事嫁接的组合 → 先查 backlog 方向与稀释史,两项有一项不过直接淘汰
6. **无楼层杀**:回答"催化剂失败后它值多少" (残值楼层)。有可计算楼层 (净现金、盈利老业务、硬资产) = 通过;楼层为零或负 (持续烧钱+可无限稀释) = 出局
7. **知情卖方警示** (降级非出局):CEO/创始人近期减持、PE 股东二次发行 → 标记,要求额外安全边际 (如低于知情者卖出价20%+,或锁定期窗口结构)。反向:内部人真金白银增持 = 加分锚点 (模式:LPK CEO €21自购 vs MP CEO $71减持、KRMN PE $61清仓)

## Stage 6:催化剂日历与四问建模 (人工层)

存活到此的标的,逐一回答**四问**,任一答不出 = 不是不对称,只是赌博:

1. **我的变量是什么?** 一句话说出"市场在X上错了,我依据Y认为是Z"。说不出 = 没有 edge
2. **下行有界吗?** 残值楼层在哪个价位,对应多少 P/S 或净现金
3. **兑现有日历吗?** 硬日期 (财报、deadline、锁定期到期、合同决标日、立法节点) 优先;无日历的催化剂只能 monitor 不能 position
4. **谁在对面?** 对手盘是量化动量盘 (可接) 还是产业资本/内部人 (先假设他对)

**赔率建模**:对每个催化剂写出 {先验概率, 兑现目标价 (用催化剂兑现可比公司估值,不用保守折价), 失败楼层价},算期望值。**方向概率不等于期望值,体系赚的是概率×赔率的乘积。**

## Stage 7:入场结构与仓位 (执行层,继承 catalyst_momentum_system_v2)

- **四层锚点**:近期发行价 / 前突破支撑 / SMA50与SMA200 / Fibonacci 38.2-50-61.8%
- **三段式建仓**,单注 $1,000-1,500:
  - 标准末端票:T1 锚点区,T2 催化剂确认突破或更深锚点二选一,T3 只给兑现后回踩
  - 已知利空事件在前 (如已预告的弱指引):T1 减半
  - 树外新枝:半注起步且不设第二注 (买的是"在场门票",不是盈利主力)
- **时间止损优先于价格止损**:事件 deadline 过期未兑现 = 无条件离场,不等"再看看"
- **组合约束**:
  - 同一宏观因子下的彩票仓 ≤ 彩票总仓位的60% (强制配置不相关域:防务/医疗/特殊情况)
  - Barbell:收税型底仓 (Q/AMZN 类) 60-70% + 彩票卫星 30-40%,比例破了再平衡
  - 价格下跌本身不是入场理由。日志里只准写锚点和催化剂,不准写"跌得够多了"

## Stage 8:监控与证伪 (持续层)

- **每条主线**:跟踪 falsification_signals 与嫁接密度,主线转 late → 自动收紧该主线下所有候选的准入
- **每个持仓**:每季只检验进场时写下的变量 (如 Q:ICS有机增速减ESI电子板块增速>8pct + EBITDA利润率方向;AMZN:AWS利润率≥38% + 与Azure增速差收敛),两项连续两季恶化才离场,中途波动无视
- **校准记录**:每笔进场公开写下概率与赔率估计,兑现后复盘"错在概率还是错在幅度"。无预测记录 = 无校准 = 永远靠感觉报概率

## Codex 运行说明

**输入**:一条主线名称或一个锚点事实。
**任务**:顺序执行 Stage 0-5,输出候选标的表。
**输出格式**:每个候选一行,字段 = {ticker, exchange, node, transmission_type, order_inevitability(1-5), purity_pct, coverage_test(3项各pass/fail), kill_rules_triggered(列表), price_history_note, 综合评级(A/B/C/坐标/出局)}。
**纪律要求**:
1. 所有数字必须附来源与日期;无法验证的标记 [unverified],禁止编造
2. pipeline/MOU/LOI 一律不得计入 backlog
3. 对每个 A/B 级候选,额外输出一段"市场为什么还没定价它"的假说;写不出假说的自动降级为 C
4. 每周增量运行:只报告状态变更 (新锚点、新红旗、覆盖/重估状态变化),不重复全量报告
